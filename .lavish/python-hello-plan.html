Plan

Build a Python "Hello" App

A minimal, from-scratch plan for a simple Python program that prints a greeting, runnable in this dotfiles environment.

Goal

A tiny Python app that prints Hello, world! (or a name-aware greeting) when run, usable as a starting point for future Python work.

Current State

No Python app exists yet in ~/khoa_agentic/dotfiles. Only /usr/bin/python3 (3.9.6, Xcode CLT) is on PATH. No uv or project-level Python is nix-managed.

Desired Behavior

Run with one command, no dependency install step, and reproducible across machines if this repo is checked out elsewhere.

Proposed Approach

  • Pick a location
  • Write hello.py
  • Decide interpreter source
  • Run & verify
  1. Location: a new top-level folder, e.g. hello-app/, keeping it separate from the nix-darwin/home-manager config files.
  2. Code: a single hello.py with a main() guarded by if __name__ == "__main__":, accepting an optional --name argument via argparse, and printing a styled greeting rather than plain text - see "Making the Output Beautiful" below.
  3. Interpreter: see comparison below - this is the one real decision.
  4. Verify: run it once locally and confirm output; no tests needed for a hello-world scope.

Making the Output Beautiful

Per feedback: the greeting should be styled, not a plain print("Hello, world!").

Plain Stdlib-only styling Library (e.g. rich)
Look Flat text ANSI color + a box-drawn border around the greeting Full styled panel, gradients, emoji, tables
Dependencies None None - just \033[... escape codes Adds rich as a dependency
Fits "Hello app" scope Too plain now Good fit Possibly overkill
Recommendation: stdlib-only styling - a colored, box-bordered greeting (optionally centered) with zero added dependencies. Reach for rich only if this is meant to grow beyond a hello-world starting point.

Comparison: How to Run Python

System python3 Nix-managed Python
Setup effort None - already on PATH Add python3 to home.packages or a flake devShell, then rebuild
Reproducibility Weak - tied to macOS/Xcode CLT version (3.9.6, quite old) Strong - pinned version, matches this repo's declarative philosophy
Fits this repo's conventions No - bypasses nix-darwin/home-manager entirely Yes - consistent with how node/casks were just added declaratively
Best for A true one-off throwaway script Anything meant to stick around or be shared
Given this repo's pattern so far (declaring node and opensuperwhisper in configuration.nix rather than installing ad hoc), the nix-managed route is the better fit unless this is meant to be a quick throwaway.

Decisions

Layout: standalone script at hello-app/hello.py - no pyproject.toml, kept as a true hello-world scope.
Interpreter: nix-managed - added python3 to home.nix's home.packages. Run ./rebuild.sh to apply; verified in the meantime with the system /usr/bin/python3.

Implementation

hello-app/hello.py - ran and verified locally (Hello, world! and --name Khoa) with a colored, box-bordered greeting.
